## 2. 产品目标

Stardot 是一个桌面随手收集待办工具。用户在阅读网页或使用其他应用时，可以将需要处理的文字投入桌面上的星星，整理为任务，再继续原来的工作。

核心流程：

> 看到信息 → 拖入或快捷键录入 → 简要识别并生成任务概要，自动提取明确日期 → 编辑或确认任务正文（也可直接保存）→ 查看或接收提醒 → 完成与归档

产品重点：

1. 录入方便，减少切换窗口和重复输入。
2. 任务内容清楚，卡片不堆放辅助文字。
3. 暖色、柔和、有适度个性，日常使用保持安静。
4. 数据可靠，兼顾视觉效果、响应速度与资源占用。

目前以个人使用和完整应用开发学习为出发点。商业化目标、收费方式和多人协作不在本轮需求范围内。

## 4. 功能需求

### F01 桌面星星入口【已确认】

- 应用名称为 Stardot，中文含义为“星点”。
- 平时以暖金黄色五角星常驻桌面，带拟人化眼睛和嘴巴。
- 五个外角进一步圆润，颜色稍亮；悬停／文字拖入时眼睛睁大，轮廓以柔和渐变微光反馈，整体不旋转或放大。
- 成功接收文字及完成任务时显示短暂表情，平时保持安静。
- 点击星星打开清单面板。
- 支持移动、靠边吸附、记住位置、临时隐藏与快捷键找回。
- 清单根据屏幕边缘选择展开方向，避免越出可用屏幕。
- 星星拖到屏幕边缘被部分遮挡时，松手后自动移回当前屏幕的可用区域，保证星星完整可见。
- 多屏、显示缩放和全屏使用场景需纳入验证；具体适配范围待定。

### F02 清单视图【已确认】

- 窄长、圆角面板贴在星星旁边。
- 每项任务为圆角卡片，以任务内容为视觉重点。
- 卡片显示必要的日期／时间和小图标，不常驻倒计时、状态说明等辅助文字。
- 支持新增、编辑、完成及恢复任务。
- 单击卡片正文打开编辑，双击编辑区正文查看只读原文，再双击返回；不另设原文按钮。
- 再次单击当前卡片，保存并关闭编辑；单击另一张先保存当前内容再切换。点击 + 先保存当前编辑，再打开空白新建。
- 收起清单同时保存并关闭编辑器和日期弹窗；空白新建直接关闭。保存失败保留内容并停留在编辑状态。
- 正文在卡片内垂直居中，日期独立放右下角，不挤动正文；提示自动消失。
- 归档卡片支持删除；当前实现提供 6 秒内撤销最近一次操作。

### F03 文字录入【已确认】

- 支持手动输入、从兼容应用拖入文字、复制后通过全局快捷键填入。
- 三种方式进入同一套编辑卡片。
- 拖入时，星星先显示接收反馈；松手接收成功后再展开编辑面板。
- 拖入操作应复制内容，保留来源中的原文字。
- Enter 用于确认识别后的任务概要为正文；Ctrl + Enter 或点击对勾可以直接保存任务，无需先单独按 Enter。
- 中文输入法选词不得导致任务被误保存。
- 默认 Ctrl + Alt + S 复制录入、Ctrl + Alt + Space 找回星星；设置中可换组。注册冲突时保留旧配置，提示更换。

### F04 概要识别、正文与原文【已确认／当前设计】

- 卡片表面不单独展示“原文”区域。
- 对录入内容进行简要识别，截取概要，放在任务正文位置供用户查看和编辑。
- 沿用灰色预览表现，但灰色对象是待确认的任务概要。按 Enter 将概要确认为正文，不保存整项任务。
- 用户可以直接编辑概要，也可以通过 Ctrl + Enter 或对勾直接保存，概要确认不作为保存的必经步骤。
- 当前保存方案：采用正文位置当前显示的内容，包括尚未单独按 Enter 确认的概要或用户已编辑的文字，同时保留原文。
- 内部保留收集时的原文；单击卡片编辑，双击编辑区正文切换原文，不覆盖草稿。
- 不强制用户分别填写标题与描述；概要应忠实于原文，不补造原文没有的任务或时间。概要提取方式在技术选型时评估，本稿不指定实现技术。
- 当前降级方案：无法提取有效概要时保留录入文字，允许手动编辑和保存，不阻断录入流程。
- 卡片当前最多展示四行，编辑时查看全文；正文与原文在同一编辑区域内双击切换。

当前输入规则：

| 场景 | 行为 | 状态 |
| --- | --- | --- |
| 输入法正在组词或选词 | 优先交给输入法处理 | 已确认 |
| 正文位置显示待确认概要，按 Enter | 接受概要为正文，不保存整项任务 | 已确认 |
| 无待确认概要，在正文中按 Enter | 换行 | 当前设计 |
| 按 Ctrl + Enter 或点击对勾 | 直接保存任务，不要求额外确认日期或先单独确认概要 | 已确认 |
| 概要尚未确认就直接保存 | 保存正文位置当前显示的内容，并保留原文 | 当前设计 |

### F05 日期自动识别【已确认／当前设计】

- 只自动识别明确的日期和时间表达，识别后直接填入任务日期／时间字段。
- 日期不经过候选确认流程，不需要按 Enter 接受；用户可以直接保存任务。
- 自动填入的日期显示为实际值，仍可手动修改或取消。
- 当前保守方案：没有明确日期，或多个日期无法确定对应任务时，不自动填入日期；保留原文，允许手动设置，不阻断保存。
- 相对日期按录入当天解析为实际日期并可见；历史消息中的“明天”等可能需要用户手动修正。

### F06 日期调整与展示【已确认／当前设计】

- 编辑时可将指针放到月、日、小时、分钟上，通过滚轮调整对应部分。
- 当前方案只在编辑状态启用日期滚轮；浏览列表时，滚轮继续用于列表滚动。
- 点击小日历或日期数字打开日期选择器，使用月历选日期；按需启用时刻，以小时、分钟下拉选择，避免手输日期格式。
- 日期入口放在编辑器左下角，与右下角的保存对勾同一行。
- 卡片默认不显示星期。当前格式为“9/18 15:00”，当天可只显示“15:00”；悬停可查看完整日期。
- 星期在日历顶部以“一、二、三、四、五、六、日”显示。
- 滚轮每步调整一单位；跨月时限制到有效日期，小时／分钟按时间进位；没有时刻只显示日期。

时间颜色约定：

| 状态 | 颜色 |
| --- | --- |
| 逾期 | 黑色 |
| 今天 | 橙色 |
| 明天 | 黄色 |
| 后天及以后 | 绿色 |

- 颜色保持可辨认；黄色偏赭黄，绿色偏暖橄榄绿。
- 当前规则为逾期优先于“今天”；只有日期的任务在当天结束后算逾期。
- 首版统一显示“任务时间”，不增加计划时间／事件时间分类。

### F07 本机提醒【已确认／当前实现】

- 支持到任务时间前发出本机通知。
- 卡片以小铃铛表达提醒状态；悬停查看规则，点击设置。
- 未设置具体时刻的任务不提醒，包括只有日期、没有小时和分钟的任务；不自动补默认时刻。
- 只有日期的任务仍可按日期进入日历，并按时间颜色规则展示。
- 用户确认新建任务默认提前 10 分钟提醒，可改为准时、提前 30 分钟或关闭。旧版任务升级后保持无提醒状态，可逐项开启。
- 当前设计：取消任务日期时，也清除依赖该日期的提醒。
- 任务完成、删除或修改日期后，相关提醒必须同步更新。
- 要考虑程序启动或睡眠恢复后的遗漏提醒检查。
- 当前建议：多条遗漏提醒合并提示，避免恢复后连续弹出大量通知。
- 当前实现：托盘运行时通过系统通知提醒，完全退出／关机时不通知；下次启动时合并未发送提醒。系统勿扰可能隐藏通知，不将“已请求发送”等同于用户已阅读。

### F08 完成与归档【已确认／当前设计】

- 勾选后任务划线、变灰，再收入归档，提供撤销反馈。
- 通过小文件夹图标进入归档内容。
- 首版当前设计将归档作为已完成任务的收纳处，不另设独立的手动归档状态。
- 归档任务可以恢复为待办；具体归档页面布局待设计。
- 完成、归档和删除不能导致同一任务数据重复或状态不一致。
- 已归档任务的卡片提供垃圾桶图标；删除支持撤销，恢复原 ID、正文、原文、日期和完成状态。

### F09 日历视图【已确认；纳入首版】

- 日历是清单之外的另一种查看模式。
- 打开日历时收起窄长面板，在当前使用的屏幕中央展开较大窗口。
- 每个日期格子排列当天任务，日期数字较小，任务内容为主。
- 清单与日历共用同一份任务数据，编辑、完成和恢复保持一致。
- 当前设计：用小圆底或细边框标记今天；任务过多时显示“+N”，点击查看当天完整列表。
- 无日期任务不显示在日历中，日历也不设置这类任务的额外入口；它们仍保留在清单中。
- 关闭日历后回到仅显示悬浮星星的状态，不自动打开清单面板；用户点击星星时再展开清单。

### F10 本地数据与恢复【已确认】

- 数据在本地可靠保存，正常重启后可以继续使用。
- 支持误操作撤销与备份导出。
- 设置提供 SQLite 备份导出／恢复，包含任务和提醒记录；导出使用 SQLite backup 接口。恢复先校验结构与数据、展示任务数量，经用户确认后替换当前任务，并自动生成恢复前备份；不合并任务。窗口位置与快捷键单独保存，不包含在任务备份中。
- 应避免保存失败时仍向用户显示保存成功。

## 5. 视觉与动效要求

- 整体使用暖色、低饱和浅色系，避免冷色调。
- 当前设计采用奶油白、米杏、浅桃背景，深棕灰正文，轻边框和少量暖色阴影。
- 星星五角稍圆润，暖金黄色，配简洁眼睛和嘴巴，小尺寸下也应清楚。
- 展开、接收、加入和完成动画自然，及时反馈操作结果。
- 当前设计：拖入时眼睛睁大并微亮，接收或完成时短暂微笑；平时静止，不持续跳动或闪烁。
- 投放与点击区域应便于操作，不要求精确瞄准星形尖角。
- 最终尺寸、色值、图形风格和动画参数由后续视觉稿验证，不在本稿锁死。

## 6. 非功能需求

| 编号 | 要求 | 验证方式 |

## 7. 首版范围与实施顺序

首版范围已确认：保留本稿已讨论的星星入口、清单、录入与概要识别、日期、提醒、完成与归档、本地保存与恢复、日历，以及相应视觉、桌面适配和性能要求。

以下为首版内部的建议实施顺序；具体排期在技术方案确定后制定：

2. 日期与可靠性：时间识别与调整、本机提醒、遗漏处理、撤销和备份恢复。
3. 日历与体验完善：日历视图、完整视觉动效、桌面适配和性能优化。

基础视觉、可靠保存与性能意识贯穿各阶段，不能全部留到最后。

日历随首版交付。其他扩展功能放到下一个大版本再考虑，当前不扩大范围；手机端和电脑手机互通继续作为未来方向。

## 10. 协作与变更方式

- 环境搭建由用户亲手完成，助手解释工具用途并指导排错。
- 开发按可运行的小功能推进：说明问题和取舍 → 实现 → 运行验证 → 讲解 → 用户参与修改。
- 新决定先更新对应需求；影响首版范围时同步调整实施顺序和验收条件。
- 需求可以随着验证结果变化。冻结首版范围的作用是明确当前交付目标，并非禁止以后修改。
