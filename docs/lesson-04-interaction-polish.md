# 第 4 轮：从截图定位布局和交互问题

本轮修正现有模块，没有增加依赖或改变数据结构。

## 1. 新的操作方式

| 操作 | 结果 |
| --- | --- |
| 单击卡片 | 打开编辑 |
| 再次单击同一卡片 | 保存当前修改，关闭编辑 |
| 单击另一张卡片 | 保存当前修改，打开另一张 |
| 编辑时点击 + | 保存当前修改，打开空白新建 |
| 收起清单 | 保存当前修改，同时关闭编辑器、日期和时刻弹窗 |
| 保存失败 | 保留草稿，停留在当前编辑，不切换或收起 |
| 空白新建后收起 | 直接关闭，不保存空任务 |
| 点击日期图标 | 在月历选择日期；按钟表图标可增加或取消具体时刻 |

双击编辑正文切换原文、Enter 接受灰色概要、Ctrl + Enter 保存、日期数字滚轮调整和日期取消继续保留。点击编辑器右上角 × 是主动取消，会丢弃本次修改。

## 2. 为什么需要统一的保存出口

原来切换卡片被“请先保存或取消”拦住，关闭清单又只隐藏窗口。这是同一份草稿被不同操作处理成了不同结果。

现在 Python 的 `TaskController.finishDraft()` 负责统一处理：

```text
没有草稿 → 继续
空白新建 → 关闭草稿，继续
其余草稿 → 写入数据库
    成功 → 关闭草稿，继续切换或关闭窗口
    失败 → 保留草稿，中止切换或关闭
```

例如修改 A 后点 B，必须先保存 A，再载入 B。这样 B 的文字就不会覆盖尚未保存的 A。点击“+”也走这个出口，避免看起来像在新建、实际上仍在修改旧任务。

## 3. 居中布局与图标裁切

原来正文使用固定 `y: 16`，所以短文字始终靠上。现在正文使用 `anchors.verticalCenter`，日期独立定位到右下角。有日期的多行卡片会留足上下空白，保持正文中心不变，并避免相撞。

日期图标原先是在按钮的内容区域画一幅固定大小的图，但按钮默认内边距缩小了内容区，图形被裁掉。现在去掉多余内边距，并重绘圆角日历轮廓。这里的问题属于布局，不是需要一张更高清的图。

## 4. 吸附应看可见轮廓

84 × 84 的星星窗口包含透明留白。以前按窗口边框留 6 像素，星星本体看起来却离屏幕还有约 17 像素。

`settle_star_position()` 现在根据可见星星边界计算位置：松手后距边缘 24 个逻辑像素以内吸附，本体距工作区边缘 2 像素。透明留白可以在屏幕外，本体保持完整。工作区会避开任务栏，坐标允许为负数以兼容左侧显示器。

微光采用暖金色、多层透明描边形成逐渐变淡的边缘；静止时不播放持续动画，悬停和离开才短暂过渡。

## 5. 清单为什么可能先闪一下

此前先显示窗口，再把内容动画从透明重新开始，存在旧的完整画面先被显示的机会。

现在顺序是：准备窗口位置 → 原生窗口透明度设为 0 → 显示窗口 → 等第一帧完成 → 淡入。收起时将透明度归零。已经展开时再次请求聚焦，不重启动画。[Qt Window 的透明度与帧信号文档](https://doc.qt.io/qt-6/qml-qtquick-window.html#opacity-prop)

错误提示原来主动停止了消失计时器，因此会一直留下。现在普通提示约 1.8 秒，错误提示约 3.5 秒；带撤销的操作仍保留 6 秒。隐藏提示不丢弃草稿。

## 6. 如何验证

```powershell
uv run python -m unittest discover -s tests -v
uv run tools/check_ui.py
uv run tools/check_window_lifecycle.py
```

前两项检查业务规则、真实模拟点击／键盘／滚轮事件及界面截图；最后一项短暂打开 Windows 原生窗口，检查首帧淡入、重复聚焦、连续开关和关闭保存，随后自动退出。全部使用临时数据库，不改日常任务。

离屏截图在 `artifacts/ui/`。原生生命周期检查可以发现淡入不启动、显示时透明度错误等问题，但不能证明所有显卡和屏幕组合下都没有闪烁；实际桌面体验仍需要继续观察。
